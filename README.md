## 可以做什么

| 功能 | 说明 |
| --- | --- |
| 三钱物理起卦 | 在浏览器内模拟三枚铜钱的运动、碰撞与落定，支持逐爻投掷或连续六爻 |
| 线下结果录入 | 已经用真实铜钱摇好卦时，可以手动录入六爻并生成排盘 |
| 纳甲排盘 | 展示本卦、变卦、纳甲、六亲、六神、世应、动爻及日期相关信息 |
| DeepSeek 解读 | 使用自己的 API Key 发起解读、继续追问、停止生成 |
| 提示词导出 | 不填 Key 也能导出问题与卦盘；交给外部 AI 后，可贴回结构化回复 |
| 两种解读 | 普通解读以文字呈现；结构化解读先看结论，再按需展开依据、候选与不确定性 |
| 历史记录 | 本机保存问答与排盘摘要；长回复可收起，详情区域可滚动 |
| 入门资料 | 基础知识与断卦入门分别组织，适合边操作边查阅 |
| 主题与移动端 | 日间、夜间、跟随系统；手机导航、统一表单控件与页面过渡 |

网站本身不收费、不提供账号体系，也不代售 AI 服务。选择 API 模式时，模型服务商会按照你的账户使用量计费。

## 快速开始

### 方式一：只摇卦、看排盘

1. 打开 [网站](https://gua.1eak.cool/)，进入「起卦排盘」。
2. 在「铜钱摇卦」中选择逐爻投掷或连续六爻，点击「开始摇卦」。
3. 在投掷窗口点击按钮，完成六爻后查看排盘。
4. 如果已经在线下摇好卦，切换手动录入，按页面爻位填写六次结果。

排盘和教学内容不需要 API Key，也不会产生模型调用费用。重新起卦时请按页面提示确认，避免把同一件事的多次结果混在一起。

### 方式二：使用 DeepSeek API

1. 在「AI 解卦」的设置中填写自己的 DeepSeek API Key。
2. 写清楚所问的事情与必要背景，从「选择」占位中明确选定普通或结构化解读，再设定回复篇幅。
3. 点击「AI 解读」。已有可用卦盘时按页面流程使用；需要起卦时，浏览器会完成起卦再发送请求。
4. 阅读结果；结构化模式可按需展开依据与不确定性。
5. 同一件事可继续追问；换问题时重新建立对应的卦盘和会话。

Key 由你向 [DeepSeek 开放平台](https://platform.deepseek.com/)申请。模型选择以当前页面提供的选项为准；费用以服务商账单为准，页面估算仅供核对。

| 解读方式 | 适合怎样使用 | 返回与检查 |
| --- | --- | --- |
| 普通解读 | 希望直接阅读文字，可选择人设与推理档位 | 自然语言回复，不走结构化 JSON 核对 |
| 结构化解读（试用） | 希望展开依据、核对引用、方便历史回看 | JSON 协议，先展示结论；篇幅和自定义语气进入提示，不使用普通模式的人设与推理档位 |

页面没有默认替你选择解读方式。直接 API 目前只接入 DeepSeek；其他 AI 可通过导出提示词使用，这不等于本站已接入 OpenAI、Anthropic 等接口。

### 方式三：导出提示词，不填 Key

普通模式可导出文字提示词，结构化模式可导出 JSON 要求并贴回核对。以下以结构化模式为例：

1. 写下问题并准备卦盘，选择结构化解读，点击「输出提示词」。
2. 复制生成的完整提示词，粘贴到你使用的外部 AI。
3. 等待外部 AI 完成，复制其完整 JSON 回复。
4. 返回本站，贴入回复并勾选已复制完整内容，再点击「核对并显示解读」。
5. 继续追问时，使用「输出追问提示词」生成与当前问答对应的新提示词。

本站生成、核对提示词本身不调用付费接口。外部 AI 是否收费、如何处理输入，由你选择的平台决定。请保留完整结构，不要只复制其中的自然语言结论。

## 结构化解读如何工作

结构化解读把卦盘事实、模型解释和不确定性分开呈现，方便回看与核对。

```mermaid
flowchart LR
    A[起卦或手动录入] --> B[统一卦盘数据]
    B --> C[问题与本轮上下文]
    C --> D[DeepSeek API]
    C --> E[导出提示词 → 外部 AI]
    D --> F[回复核对]
    E --> F
    F --> G[自然语言结论]
    G --> H[展开依据与不确定性]
    F --> I[未通过时显示原因并保留原文]
```

### 当前会检查什么

- 回复结构是否完整、必要字段与引用是否存在。
- 回复是否属于当前卦盘和问答轮次，避免把另一轮结果贴回来。
- 部分明确的「某爻为动爻／静爻」陈述是否与本卦事实冲突。
- 程序事实与规则标注分开显示，规则可展开查看来源事实。

### 当前不会保证什么

**格式与引用检查通过，不等于解释正确，也不等于预测可靠。** 动静核对只覆盖有限的明确表达，不是完整自然语言事实审查；象意推论、回答是否充分和现实结果仍需要人工判断。

新版会话采用 `reading-production-4`：校验失败的原文保留在本地，但不继续带入后续追问。旧版历史仍可查看，格式兼容；当前页面不再自动恢复旧会话。新建解读增加紧凑要求，API 与导出提示词一致。

长结论支持展开／收起；依据默认收起，同一分析段内的事实去重，规则关联本段事实编号。复制使用完整内容，页面收起不删减保存内容。生成追问时保留当前轮次的阅读展开状态。

回复篇幅是生成目标，不保证精确字数。结构化模式支持篇幅与自定义语气，不沿用不适用的人设、推理档位设置。没有依据时应说明不确定性，而不是为了达到字数补造内容。

## 物理摇卦与快速起卦

**AI 页的快速起卦也运行物理模拟。** 它和可见的摇卦窗口共用物理世界创建与落定判定逻辑。

| 对比 | 手动点击物理摇卦 | AI 页面快速起卦 |
| --- | --- | --- |
| 结果来源 | 铜钱模型落定后的朝向 | 铜钱模型落定后的朝向 |
| 过程 | 随动画逐步播放，可逐爻投掷 | 连续计算六爻，不等待完整动画播放 |
| 为什么速度不同 | 等待画面播放、落定和下一轮操作 | 按批次推进模拟，省去可视化等待 |
| 执行位置 | 本机浏览器 | 本机浏览器 |

点击时间、位置等参与初始化运动状态；两种入口的初始条件不完全相同，因此不要求结果一致。判定结果时没有直接随机抽取卦象，也没有由 AI 决定卦象。

这是软件物理模拟，不是通过手机传感器识别真实铜钱，也不意味着模拟分布已经被证明等同于现实投币。

## 历史记录与数据存储

- 历史记录、设置及已保存的 Key 位于当前浏览器的本地存储，不跨设备自动同步。点击保存后的 Key 以明文写入 `localStorage`，输入框打码仅用于显示，不是加密。
- 刷新或重新进入网页时，问题输入框清空，解读方式回到「选择」；当前卦盘、输出和追问也会清空；离开页面满 30 分钟返回时同样重置。短暂切到其他应用保留当前内容，已保存历史、设置与起卦次数不受影响。
- 历史列表最多保留 **200 条**；最近一次结构化会话最多 **8 轮**，刷新后到历史记录中查看，当前页面从新的一卦开始。
- 结构化 API 解读与提示词路径都会记录对应状态；只导出提示词不代表已经获得 AI 答案。
- 超过 **300 字**的历史问答默认收起，可展开全文；单条记录详情限制高度并可内部滚动。
- 复制结构化对话包含折叠的依据与不确定性；删除记录需要确认。
- 清理浏览器数据、更换浏览器、使用无痕窗口或浏览器存储回收，可能使本机记录不可用。重要内容请及时复制留存。

```mermaid
flowchart TD
    A[浏览器：问题、卦盘与设置] --> B[本地历史与会话]
    A -->|选择 API 解读| C[DeepSeek 接口]
    A -->|导出提示词| D[本地生成文本]
    D -->|用户自行复制| E[外部 AI 平台]
    F[Cloudflare] -->|提供静态网页资源| A
```

项目没有自建业务后端。API 模式下，Key 用于向 DeepSeek 鉴权，问题、卦盘及必要上下文会发送给 DeepSeek；这不代表 Key 永远不会离开设备。不要在共享设备保存 Key，也不要把 Key、私人问题或完整个人历史提交到 Issues。

## 本地开发

### 环境

- Node.js **24.15 或更高**；仓库 CI 使用 24.18.0。
- npm，以及 Git。
- 当前浏览器回归以 Windows + Microsoft Edge 为主，部分脚本也使用 Playwright WebKit。

### 启动当前网站源码

```sh
git clone --branch main https://github.com/1eakkkk/liuyao-tool.git
cd liuyao-tool
npm ci
npm run dev
```

打开终端输出的本地地址。源码使用 Vite 与原生 ES Modules，请通过开发服务器访问，不要直接双击源码 `index.html`。

### 构建与检查

```sh
# 单元与回归测试（与 CI 一致，冻结验收要求已跟踪修改先提交）
npm test -- --maxWorkers=1

# 构建，并检查生产资源边界及生成资产清单
npm run release:check

# 本地预览 dist
npm run preview
```

浏览器检查需先完成构建，脚本会启动自己的预览服务：

```sh
npm run test:browser
npm run test:browser:reading
npx playwright install webkit
npm run test:browser:usability
npm run test:browser:controls
```

完整检查列表见当前源码分支的 [GitHub Actions 工作流](https://github.com/1eakkkk/liuyao-tool/blob/main/.github/workflows/verify.yml)。部分脚本固定使用 Edge，不应假设所有脚本都能在未安装 Edge 的系统上直接运行。

自动化界面测试主要使用模拟 API，不等同于真实模型验收。真实 DeepSeek 测试单独管理 Key、调用预算与结果记录，不是启动或构建网站的必需步骤。

README 截图可以在构建后重新生成，脚本使用干净存储并拦截模型请求，需要本机安装 Edge：

```sh
node scripts/capture-readme.js
```

## 部署到 Cloudflare

当前生产使用 **Cloudflare Workers Static Assets**，提供纯静态网站，不是 Cloudflare Pages，也没有业务 API 后端入口。

| 项目 | 当前配置 |
| --- | --- |
| Worker 名称 | `liuyao` |
| 正式域名 | `gua.1eak.cool` |
| 配置文件 | `wrangler.jsonc` |
| 构建输出 | `dist/` |
| 构建命令 | `npm run release:check` |

自行部署时，先将 `wrangler.jsonc` 中的名称改为自己的 Worker 名称，并在自己的 Cloudflare 账户配置域名。不要在前端构建变量中放入共享 API Key，静态资源中的密钥会暴露给访问者。

```sh
npm ci
npm run release:check
npx wrangler login

# 检查配置与打包结果，不发布
npx wrangler deploy --dry-run

# 确认账户、Worker 名称和资源后发布
npx wrangler deploy
```

仓库的 Verify 工作流负责测试，不能把检查成功当作已经部署。发布后应核对线上资源、手机布局、起卦、提示词和历史恢复；保留上一版本用于回滚。版本发布与回滚记录见下方文档入口。

## 常见问题

<details>
<summary><b>没有 API Key 可以使用吗？</b></summary>

可以。起卦、排盘、学习资料和提示词导出不要求 Key。只有本站直接调用 DeepSeek 时需要你的 Key。

</details>

<details>
<summary><b>为什么解读显示 700–800 字，实际却短很多？</b></summary>

篇幅设置会进入结构化提示词，但它是目标，不是硬性字数保证。简短问题、依据不足或模型未遵循要求都可能使结果偏短。可以围绕遗漏的具体问题追问，不建议仅为了凑字数反复生成。

</details>

<details>
<summary><b>为什么贴回回复后没有正常展示？</b></summary>

确认复制了当前这一轮的完整 JSON，而非部分结论或另一轮回复。页面会区分不完整、格式、引用、轮次和部分事实冲突等原因，并保留原文。通过结构检查也不代表所有解释均正确。

</details>

<details>
<summary><b>为什么提示暂时不能继续摇卦？</b></summary>

当前设有本机 10 分钟最多 3 次的起卦限制，页面会提示可用次数。取消或未完成的物理起卦不会按成功起卦计数。同一件事建议保留原卦继续追问。

</details>

<details>
<summary><b>手机摇卦是不是要长按？铜钱立住怎么办？</b></summary>

当前操作是点击投掷，无需长按。铜钱未稳定平放时会自动尝试重投；达到重试次数仍未落定时，按提示再投。反馈问题时请附机型、浏览器、系统版本与具体操作。

</details>

<details>
<summary><b>安卓或 Windows 安装包还适用吗？</b></summary>

仓库 [Releases](https://github.com/1eakkkk/liuyao-tool/releases) 可能保留历史安装包。当前维护与本文验收范围以网页为准，不能根据网页更新推断旧版 App 壳的兼容性；建议优先使用浏览器访问正式域名。

</details>

<details>
<summary><b>知识库增强已经上线了吗？</b></summary>

尚未上线自动注入。稳定版的结构化协议、程序事实和规则标注，与实验中的知识库增强不是同一件事。研究代码或 Phase 文档存在，不表示相应功能已经通过生产验收。

</details>
