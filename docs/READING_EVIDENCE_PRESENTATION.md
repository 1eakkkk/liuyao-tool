# 结构化解读：依据去重与中文规则展示

日期：2026-09-30。继续现有结构化解读的质量收尾，处理“同一程序事实与规则来源重复展示”的确定性问题。本轮是现有线上功能的展示修正，不接入离线知识协议。

## 用户看到的变化

每个因素或候选的依据中，原始事实只列一次；规则另列，并指向本段事实编号。原先直接引用某事实、再展开规则查看相同来源，需要重复阅读；现在同一事实合并显示，规则仍保留所有来源关联。多个规则共用事实也不会增加事实条数。

仅引用规则时，其来源事实仍完整呈现，不隐藏。去重只发生在同一分析段，不跨段合并，以免用户无法判断具体解释使用哪些事实。编号在每段内重新开始。

依据整体继续默认收起，结论先显示。去掉每条规则内部第二层来源展开，减少手机上的嵌套。规则显示中文爻位、规则名称与方向；内部 rule_id 仍保留在证据、原始 JSON 和模型输入中，展示不删除追溯信息。

复制全部对话、结构化历史归档与页面共享同一依据整理函数，避免页面去重后复制内容仍重复。旧历史记录的格式没有强制重写；恢复中的旧结构化会话仍通过既有协议重新核对。失败原文、引用错误说明和复制失败原文的行为保持原样。

## 改动边界

- 不修改排盘值、规则计算、模型请求、提示词或输出协议。
- 不修复或重写模型文字；值与引用检查通过仍不证明解释正确。
- 不把去重后的条数当作分数或独立证据数量，不提高判断倾向。
- 不导入知识模块或研究实验到生产构建；唯一新增生产模块是依据展示工具。

## 验证

8 项新增测试检查：直接引用与派生引用去重、多个规则共享来源、来源完整、假值保留、未知／缺失／错类型引用拒绝，以及页面与复制内容一致。

浏览器验收使用模拟 API，覆盖 Chromium 与 WebKit 的 1280／390px：API 回复、提示词贴回、旧轮次回复拒绝、刷新恢复、断流、取消、历史删除及复制。额外核对每段事实只出现一次、规则来源编号正确、没有规则内层展开，并保存手机截图。WebKit 模拟不等于真实 iPhone 全机型验收。

本轮无付费接口调用。真实模型的相关性、出处归属问题仍按此前记录保留，知识增强尚未达到上线条件；不能因此宣称整个解读质量阶段已完成。
