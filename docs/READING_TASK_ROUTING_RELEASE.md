# 2026-10-05 解读任务分流修正

方向仍是回答完整、程序事实可核对、解释有边界，本轮不扩大古籍知识库、模型或界面设置。

## 修复的实际问题

上一版遇到“能打到王者吗？请给两项建议”时，仅因为建议关键词就固定为纯建议，趋势部分无法输出。否定、引用“只核对”，以及事实和建议的组合也可能被硬性分流吞掉。

新会话使用 task_policy=2：

- 明确趋势或时间请求与建议并存时保留完整解读，建议词不覆盖趋势。
- “不要预测日期”只排除日期意图，不抹掉仍在询问的成败问题。
- 否定或引号里的分流词不作为纯事实指令。
- 所支持的明确事实核对与一般建议同时出现时，事实由程序展示，模型回答建议，不遗漏其中一项。
- 六神、旬空、伏神等未纳入本次自动事实核对的属性，明确说明“本次未核对”，可查看卦盘详表；同时要求的建议仍保留，不用六亲代替未知字段。

识别是有限的确定性规则，自动事实范围仍限六亲、五行、动静、世应标记、地支／纳甲、月令。不能称为通用中文意图理解；涉及未识别表达时保留完整解读能力，不以固定模板冒充读懂。

## 旧记录与验证

结构化 JSON 协议仍为 structured-selection-2。新策略写入上下文、上下文哈希和保存记录；旧保存记录缺少策略字段时按原策略1恢复，原回复、引用和导出身份不重新分类。API 和提示词导出使用同一分流。

本轮510项解读相关检查通过；随后新增混合事实建议及不支持字段提示，最终30项相关检查通过。Chromium 与 WebKit 各1280、390、320px 的导出贴回、API模拟、追问、停止、历史、重摇替换和刷新通过；浏览器包含趋势+建议请求的 schema 检查，确认不再被固定为 unclear。原浏览器脚本换题后停在确认弹窗，修复测试用例后通过，未修改产品确认流程来绕过测试。

独立 Luna 复核参与：检查发现两种额外漏答（逗号连接的事实+建议、未支持属性+建议），均已明确处理。内容模型没有新增真实测试，本轮付费调用为零；工程检查不宣称模型已全面理解混合问题或提升预测效果。
