# 总目标、阶段进度与剩余工作

更新：2026-09-24。本文区分原始 `REFACTOR_PLAN.md` 的里程碑与后续实验的实际范围。阶段编号不是完成证明；历史报告里的“完成”只适用于其当次范围。

## 总目标

在纯静态、非盈利、个人／小圈子使用的约束下，让程序负责正确且一致的排盘事实，让 AI 根据明确的事实、规则和可追溯文献解释问题，并能记录版本、检查矛盾和追踪真实结果。

工程上的成功是：不重算或改写程序事实；引用有出处；事实、规则和 AI 判断可区分；信息不足能够明确说明；修改前后可比较。预测表现需要另行收集真实结果，不从代码测试或文献引用数量推断。

稳定网站已经完成上线，但原计划的研究与验证目标尚未全部完成。

## “结构化”究竟完成了哪些

1. **卦盘结构化：已完成。** Canonical 是统一数据源，UI／存储／AI 投影围绕该数据工作。
2. **AI 输入结构化：已完成三个层次。** 1.0 是事实输入；1.1 加确定性规则；1.2 加文献。1.0／1.1 有显式调试路径与浏览器测试，1.2 仍是离线实验。
3. **AI 输出结构化：离线最小闭环已实现。** 新增独立输出协议、上下文绑定、引用／用神目标校验、失败回退和折叠详情原型，见 [M2 报告](STRUCTURED_OUTPUT.md)。现有生产 Structured Prompt 仍要求纯文本；新协议尚未接入真实 API、追问会话或普通用户入口，不能称为生产功能完成。
4. **完整产品接入：尚未完成。** 不能因为输入层存在，就说普通用户已经使用完整结构化推理链。

结构化输入不必改变用户看到的自然语言回答；输出结构化则用于校验和分层展示。两者目的不同，也要分别验收。

## 测试是否完善

现有自动测试较完整地保护已有工程行为：固定事实、旧版兼容、数据白名单、规则契约、实验冻结、存储故障、模拟流式 API、追问／恢复和桌面／移动布局。GitHub 已执行过完整发布检查。

仍缺少：

- 面向本站实际 DeepSeek 的结构化方案效果比较；模拟 API 只验证请求和界面链路。
- 自动知识检索的新独立评测与生产接入验证。
- AI 结构化输出的真实 API 接入、追问与持久化恢复测试；M2 已补齐离线格式、引用、截断流和回退检查。
- A 级经典案例的结果评测，以及真实前瞻反馈闭环。
- Android／Windows 壳程序实际验收；仓库未包含其源码。

需同时阅读两个数：**测试是否通过**，以及**被测系统是否达到目标**。测试可以正确确认一个实验系统仍然存在缺陷；因此当前 360 项工程测试通过，也不表示任务规划的 64 个样例全答对或真实模型效果已验证。

## 后续按可交付里程碑推进

### M1：知识任务门槛修复（本轮已知问题修复完成，仍离线）

保留旧实现／冻结结果，新增明确标注“已看过失败样例”的候选版本；修复已知误注入与异常；既要测禁止注入，也要测正常需求不能全部被拒绝。结果见 [任务范围修订报告](PHASE_8B_3_TASK_SCOPE.md)。修复已知安全失败后先收口，不通过无限补关键词宣称自然语言理解已解决。

### M2：结构化输出的离线最小闭环（已实现）

已定义版本化输出协议，保留自然语言结论，附可校验的事实／规则引用和不确定性；实现独立校验器、错误报告、普通文本回退和离线样例。用户已选择结论优先、详情可展开。默认输入模式保持不变，没有自动知识检索；程序引用和值经过校验，解释文字的语义真实性仍未自动核验。

验收：有效输出保留原意；无效 JSON／缺字段／虚构引用／被截断回复均有明确结果；不会把模型填的“信心”显示成预测概率；导出提示词与直接 API 的行为差异被明确记录。

### M3：结构化方案的真实效果验证与可选入口

2026-09-24 用户选择先完成离线版，真实 API 测试之后再定。未授权测试 Key 与费用上限前，不调用付费接口。M2 完成不等于 M3 已验收。

同日完成用户授权的 [Luna 小样本预评测](LUNA_OUTPUT_PILOT.md)：3 个生成代理各回答一次，另一个同模型代理审查；机械校验 3/3，语义 2 例通过、1 例现实推论无法验证。发现内部字段出现在用户文字、部分引用相关性未解释的问题。该试验未调用 DeepSeek，不替代真实服务接入验收，未改变生产版本。

后续 [p2 可读性修订与 DeepSeek 准备](DEEPSEEK_OUTPUT_SMOKE.md) 已完成：3 个新开发问题机械校验通过，中文与引用说明审查通过，现实推论仍不判为可靠。新增有预算门槛、无重试的本地接口测试脚本，366 项离线工程测试通过。用户已填写 Key；真实接口费用上限仍待确认，尚未产生本轮 DeepSeek 请求。

用实际服务模型比较稳定 Legacy 与候选结构化方案，提前冻结案例、评分、版本和成本预算；衡量事实错误、矛盾、遗漏、引用和成本。真实调用需已有可用 Key 与明确预算，不能用模拟回答冒充。满足标准后才增加普通用户可选入口，保留回退；默认切换需依据实际结果。

自动知识注入要另外通过新的独立评测。旧 holdout 已曝光，只能继续作为回归；同一实现者编写并查看的新例也不能称为独立盲测。完整协议仅 1/64 匹配的问题需逐项区分证据跨度、任务／范围、概念选择和输出约束，保留原严格指标，不在看到结果后取消不利评分。

### M4：回到原计划的经典案例 Benchmark

先建立 Case Schema 和 10 个可核对的试点案例，核验问题、日期、完整卦盘、原断与结果，再逐步扩展到原计划的 100～300 例。缺结果不补造；B／C 级材料不进入结果评分。经典拟合与真实前瞻表现分别报告。

### M5：本地预测锁定与反馈

为预测保存独立 ID、卦盘和回答哈希、版本、结果判断标准与截止期；反馈作为新记录追加，支持导出／导入。纯浏览器的哈希只能辅助发现修改，不能提供可信第三方时间戳，也不能保证用户无法改本地数据。保持无后端约束，不夸大不可篡改性。

### M6：真实结果积累后的优化

按原计划，完成案例超过 100 才开始系统比较版本，超过 500 再考虑更复杂的统计或权重。这些是项目阶段门槛，不是样本量足够的统计证明；需要同时检查选择偏差、重复案例、失访和结果定义。
