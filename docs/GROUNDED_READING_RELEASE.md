# 来源与回答边界：稳定版发布验收

日期：2026-10-05。大阶段目标：在稳定结构化协议上完成事实来源、用户前提和回答范围约束，API/导出一致、历史兼容、有限真实检查及上线闭环。不是提高模型能力或认证预测准确率。

## 本版行为

新会话仍用 judgment_policy=2，另加 grounding_policy=1；不启用失败的 policy3/4 必填对象、取舍字段。旧会话缺少来源版本时恢复为0，不改变旧请求和结论。

整合提示词区分用户陈述、程序记录、公开背景和模型解释。已部署描述标为用户提供，不认证当前可访问性或稳定性。程序展示事实和出处，模型选择编号并解释关联；不要求列满因素或硬凑字数。基础方向不能直接算有效助力，规则标注不自动证明现实属性。一般建议与盘面判断分开。

新增窄字面门禁：已知无来源现实断言、去掉否定/条件的截引、抹掉已提供部署前提、未询问却增加短期结果。部署描述排除否定、计划和条件前件（含同句逗号）。明确否定证据不当成肯定断言；句末和转折后的独立断言继续检查。门禁不是通用自然语言事实核验，其他措辞和解释有效性仍可能漏检。

## 有限真实检查

冻结两条开发题和重建手动卦盘（不是盲测），最多两次，不自动重试，失败停止。实际只调用第一条私人免费娱乐项目问题；第二条未调用。

原回答明确否定“有依据证明代码能跑/投入产出合理/平台推动”，最初被字面检查误拦。已修正这一工程错误，原始请求、回复、检查均保留；离线复查原回复仍因 direction=mixed 却只有 neutral/conditional 因素而拒绝。不得把修复误拦记为回答合格，也不自动改标签为unclear。

独立Luna内容审查确认：回复保留用户已部署描述，区分未核实的访问/稳定状态；待核事项不构成预测。但方向不一致使整条回复不通过，象意角色解释也未得到认证。这不阻止发布已验证的窄门禁。

阶段验收分为工程门禁和模型内容两层。工程需通过版本/历史兼容、完整引用与否定条件对照、方向检查、构建发布边界、两浏览器三个屏宽及线上资产/页面验证；真实失败需如实保存并停止。模型内容不是本阶段已通过项。
