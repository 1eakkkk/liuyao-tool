# 2026-10-05 判断标签与依据的一致性约束

本轮改的是模型回答的约束与检查，不是模型能力、解释正确率或预测准确率。

## 可确定的缺口与修正

旧版能接受仅有阻碍因素却标注“偏有利”、或没有两侧因素却标注“利弊并存”的结构化回复。新会话使用 judgment_policy=1：

- favorable 至少有一个 support 因素。
- unfavorable 至少有一个 oppose 因素。
- mixed 同时有 support 与 oppose。
- unclear 允许条件、中性、单侧或两侧因素，不强塞有利/不利依据。

这是声明标签一致性的必要条件。程序不按因素数量决定方向，不从五行生克自动推导有效助力，不评估自然语言解释是否成立。两侧并存仍可偏有利、偏不利或依据不足，提示词要求交代主要依据与取舍；mixed 不要求势均力敌。不得为了通过检查换标签，作用未确定时保留 conditional/neutral。

## API、提示词及历史

API与提示词导出共用相同上下文和约束。检查失败使用 direction_basis_mismatch，页面明确解释标签冲突，原文保留；不自动修复、不自动付费重试，失败回答不会作为已验证历史内容传给下一轮。

判断策略写入上下文身份与保存记录。缺字段的旧会话按原策略0恢复并继续，不重新判定历史，不默默升级旧会话。只有新会话默认启用新约束。回复JSON版本不变。

## 有限验收

34项针对性检查通过，随后37个解读检查文件、516项检查通过。覆盖12组方向/标签对照、纯事实与建议、未支持事实提示、新旧历史恢复、待发送导出身份、后续轮次、非法保存版本和错误说明。

独立 Luna 只读复核无发布阻断，采纳了避免将mixed理解为势均力敌的措辞建议。浏览器需核对新构建的标签冲突拒绝、API模拟、导出贴回、历史和移动布局。测试不是实际模型回答验收，本轮不调用付费API。

## 边界与下一步

模型仍可能把错误解释贴上合法标签，此门槛不能自动识别；语义争议不被伪装为工程通过。下一步用有限真实样本检查取用、有效作用与最终取舍，分别记录硬性错误、解释争议及未覆盖范围，不靠反复重试追求通过。
