# 结构化 API 接收与错误诊断修复

日期：2026-10-05。范围：接口接收、校验诊断、历史恢复和失败显示。未调用付费接口。

## 已确认的问题

本站使用 `response_format: {type: 'json_object'}`。DeepSeek JSON 模式约束 JSON 语法，不能代替本站对字段、编号、上下文和解释约束的校验。合法 JSON 也可能被正确拒绝，例如新增协议外字段 `judgment.basis_ids_note`。这不是用户本次故障的确诊；没有取得该次原始回复。

官方说明：https://api-docs.deepseek.com/guides/json_mode/

接收层已有流结束状态与错误，但旧调用链仅传递 `completed` 布尔值。再次解析和历史恢复把截断、断流等原因合并成 `incomplete_response`，使界面难以分辨接收错误和协议错误。

## 修复

- 将受白名单限制的结束原因、流错误和结束标记随 API 解读记录保存、恢复。任何异常只能降低完成状态，不能把部分回复提升为有效结果。
- 分别说明输出上限、超时、主动停止、缺少结束标记、流解析异常、JSON 无法读取、字段及引用约束失败；显示可用的出错字段位置。
- 保留失败原文及用量；不删除未知字段、不补写模型字段、不自动重试，不将失败回答加入后续有效对话。
- 新的外部贴回仅额外接受完整外层 JSON 代码围栏和开头 BOM，保存原文并标注包装规范化。API 保持严格 JSON，旧历史维持原判定，不提取嵌入片段。
