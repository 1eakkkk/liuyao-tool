## 实际复杂度发现

这条回复把全部五个关系局部依据写成 rel: 包 ID，而 basis_ids 需要原 registry 的 rule.id；同时未在 packet_ids 选对应关系包。两个问题独立存在，不能简单去掉 rel: 前缀修正。f1 月合、f2 月休、f3 飞伏及六亲身份还存在本段局部覆盖缺漏。原检查先在 mixed 主次规则失败，后续引用问题没有成为首个错误。以上证明本例出现了双层选择/双命名空间混淆，不足以证明这种设计对全部模型或新问题普遍更差。

程序原值、问题对应解释、现实建议分开展示仍有价值；它没有保证模型遵守分层，结论依旧放入操作策略、因素文字依旧复述属性并推出现实搜索效力。结构修订未建立语义达标。

## 最小后续建议

1. 新离线候选可比较单层局部选择：每因素只声明一种 basis_ids，由程序生成所属记录与关系来源，不再让模型同时维护 packet_ids 和 basis_ids。事实/规则仍按原 stable ID 精确解析，规则自动展开严格 source_facts 和必要参与者身份。焦点仍只由本段明确身份或实际参与关系覆盖，不能借全局背景。
2. 不为旧回复自动加包、补身份或把 rel: 静默转换为 rule:。可在离线诊断中分别列出主次失败与所有引用失败，保留原首个检查错误，避免把未走到的验证误当通过。
3. 若仍保留双层协议，至少用本例五个错误做负例；正例明确关系包 ID 与 rule.id 的不同归属。对照还应包含只去前缀但未选关系包、跨因素借月休、只选动/回头记录却借六亲、规则实际参与者覆盖焦点。
4. 保留错误散文仍可机械通过的反例。建议独立显示不证明它非必要条件，也不能用免责声明抵消正文的室内搜索效力断语。取法和主次不足时可不判断方向，不把 schema 扩张或关键词过滤当语义审核。
