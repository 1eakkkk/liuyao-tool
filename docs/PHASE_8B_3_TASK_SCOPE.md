日期：2026-09-24。状态：`post-holdout development candidate`，**不是新 holdout 验收，不可生产接入**。

## 范围与历史边界

8B.2 实现报告记载的“holdout 未曝光”仅是其提交当时状态。用户已有本地 `PHASE_8B_2_HOLDOUT.md` 和封存报告表明，32 个 holdout 已执行并暴露：4 例错误 Knowledge 注入、2 例排除违例、1 例异常。本轮不修改该本地记录，不重跑原 one-shot 执行器，不更改历史评分、冻结 benchmark、旧 1.2 实现、Schema、规则或语料。

新增 `query-plan-task-scope.js` 是独立候选，协议仍为 query-plan-1.2，实现标识为 `task-scope-revision-1`，后续应连同源码提交／哈希辨认，不能用相同协议号冒充旧实现。

## 修订内容

- 显式否定卦例上下文的理论请求优先于被否定的“本卦”词语，修复无卦盘时错误抛异常的已知情形。
- 检查覆盖整条回答的排他格式限制；若同时请求文献，输出有对立证据的 ambiguous 计划，不检索。局部先编号再解释不因此被禁止。
- 区分描述性的旁注／背景标签与明确的解释请求，避免把背景概念升级成第二个检索主题。
- 用分句和相邻概念边界绑定排除要求；识别待办、留白、未处理等明确延后指令；同概念重复出现时不能通过先出现的正向提及绕开排除。

保留保守的准入、卦盘锚点、最多两主题等门槛。本轮不扩充语料、不补造别名、不解决全部复杂语义。

## 评测方法与结果

`eval-task-scope-regression.js` 对原 32 个 development + 已曝光 32 个 holdout 分别运行旧版与候选。所有 64 例均标为已曝光回归，`independent_holdout: false`、`production_ready: false`。输出使用独占创建，拒绝覆盖先前结果。原 one-shot 结果目录完全不参与写入。

| 指标（64 例） | 旧 1.2 | 候选 |
| --- | ---: | ---: |
| 运行异常 | 1 | 0 |
| 错误知识注入的案例 | 4 | 0 |
| 明确概念排除违例 | 2 | 0 |
| 全局禁止／缺锚点／未准入注入 | 0 / 0 / 0 | 0 / 0 / 0 |
| 漏选案例 | 9 | 9 |
| 选择集合完全匹配 | 50 | 55 |
| 任务分类匹配 | 50 | 52 |
| 问题范围匹配 | 51 | 54 |
| 完整严格协议匹配 | 1 | 1 |
| 确定性重放 | 63 | 64 |

异常案例没有被当作零风险成功案例；各指标可能重叠，不相加算总错误率。原 development 集的选择集合保持全部正确。9 例漏选仍是已知问题，不能通过全部不检索掩盖。

完整严格协议比较包含精确证据跨度、输出约束等全部原标签字段，不能把 1/64 简化为“63 例概念选错”，也不能因为选择层有所改善就删除严格指标。

另新增合成开发对照：理论请求不提供卦盘、整段格式冲突与顺序混合任务、背景标签与直接解释、局部排除的顺序／重复／待办／留白／未处理。它们由同一实现者编写，是回归测试，**不是独立未见评测**。
