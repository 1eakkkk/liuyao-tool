# 2026-10-05 基础五行关系与局部引用候选

目标：针对上一轮“官鬼金不生世爻水”的作用冲突，先让程序明确基础关系、附原始事实编号，减少模型自行重述。**本轮只有离线与浏览器运行检查，付费 API 调用为零；候选尚未接入正式页面、未部署，也未完成真实回答内容验收。**

## 已完成

`src/ai/output/relation-reference.js` 从受信任的本轮上下文与程序事实计算六个本爻分别对世爻的基础五行方向，以及动爻的变爻对本爻方向。支持相生、相克、受生、受克、比和；每条保留两端五行、世爻或动爻身份的原始证据编号和程序生成的关系文字。

它不推导有效生扶、用神、喜忌或吉凶，不按关系数量打分。金生水是基础关系；若解读认为在当前卦中无效或不利，仍需说明额外条件、取用及对应依据，不能直接否认基础相生。

`experiments/reading-quality/relation-reading.js` 提供候选共同请求准备方法，将 `element_reference` 加入 API 与提示词导出的同一个数据对象，提醒模型重点解释作用和取舍、减少属性重述。表格是既有事实的派生对照，不作为新的独立证据，不改原回复协议或默认请求。表格可由同一已绑定卦盘确定性重建；本轮没有修改旧会话哈希或把旧回复当新回复认证。

## 有限文字审计

`element-claims.js` 只核对命名明确的本爻对世爻直述，例如“第3爻生世爻”“第三爻与第五爻不生世爻”。单独报告基础关系冲突与本段缺失的直接引用。

- 同一子句明确命名爻位才绑定；不从其他段或整组引用猜“两爻”指谁。
- 含条件、疑问、引语、可能、变爻／伏神或“实际／有效”等限定的段落保守标为未评估。
- 缺引用标为 `incomplete_citations`，不算完整检查；`direction_consistent` 只描述基础方向，不代表解释正确。
- 没有“全文通过”或“预测正确”结果。未匹配文字是未评估，不是通过。

原真实长段“但两爻没有直接生扶世爻”未明确在该子句命名爻位，回放保留未评估。程序表明确第三、第五爻金对第四爻水均相生；原作用冲突仍来自人工明确绑定后的审查，**没有宣称窄审计器自动抓到了整个旧段落**。没有重写旧回答以制造通过记录。

## 验证与独立审查

三个相关文件、26 项检查通过，涵盖完整 5×5 五行方向、原编号存在、回头方向、API/导出一致、默认请求不变、命名与引用不符、缺引用、条件及代词隔离。Chromium/Edge 与 WebKit 实际浏览器运行候选准备函数，两端请求/导出表格相同、所有来源存在，付费请求均为零；不是新的模型回答或真机预测验收。

独立 Luna 首次审查指出从引用猜代词、缺引仍可能被误读为完整通过的风险；已删除代词猜测，单列缺引状态并补对照检查。原回复与冻结原卦的投影精确一致后才进行本地复放，复放不调用网络、不修复原回复。

检查工具：`scripts/verify-element-reference-browser.js`、`scripts/audit-element-relations.js`。后者需显式提供已有响应报告与冻结计划；不默认依赖可删除的 `test-results` 文件，也不会自动补调付费 API。结果在本机 `test-results/element-reference`。
