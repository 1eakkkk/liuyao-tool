# 结构化解读可选入口

日期：2026-09-25。用户要求下一阶段覆盖 API 与提示词，并希望本阶段上线。

## 已实现的产品链路

- AI 页面新增普通／结构化解读选择；普通模式仍为默认。结构化模式明确标为试用。
- API：所选 DeepSeek 模型、非思考模式、JSON 输出、8192 输出上限，直接使用未经 Markdown／日期清洗的原始流。最多等待 180 秒；停止、中断、截断、缺少结束信号不显示为通过。无自动付费重试。
- 提示词：与 API 共用系统要求、卦盘、问题、历史及输出协议；导出后贴回完整回复并主动确认完整性，再在本地核对、分层展示。外部模型的结束信号无法由本站观测。
- 结论优先，依据、用神／应期候选和不确定性折叠显示。程序事实与模型解释分开呈现，引用的值从程序快照取出。
- API 与外部提示词可交替追问同一会话。每轮身份绑定本卦、当前问题及历史，旧轮回复不能充当新轮答案。
- 最近一次结构化会话单独保存在本机，最多 8 轮。刷新时由卦盘和原文重新校验，保存的“通过”状态不被直接信任。新排盘及清空时作废旧会话。此版本不是历史库的多会话管理功能。
- 生成期间锁住换卦、模式和其他输入；保留停止按钮。纯文本渲染模型内容，不执行 HTML 或模型链接。
- 结构化模式使用固定解读要求，沿用用户选定模型；不应用普通模式的人设、风格和努力程度设置，页面已说明。

## 真实模型开发测试与限制

进行了两组各 8 次真实调用（每组 Flash 7 次，包括一轮追问；Pro 1 次）。卦例和问题用于开发回归，已被开发过程看过，不是盲测或真实预测效果评估。

第一组 `reading-production-1`：8/8 格式通过，但发现伏神缺失记录的引用不相关、窄问题扩展其他字段和建议论证牵强。未据此直接发布。

第二组 `reading-production-2`：补充伏神／变爻 `null` 记录的可引用来源，只说明“未记载”，不把它当作确定不存在；收紧窄问题和引用覆盖要求。7/8 格式通过；一例新增顶层 `evidence_ids` 被拒绝并回退。伏神错误引用在该次复测中消失。仍观察到额外卦名、建议范围扩展、未经充分支持的象意和应期附加说明。**不能宣称任意问答范围和引用语义均已解决，不能宣称结构化提高预测准确率。**

这两组共 16 次调用，按比当前定价更保守的预留单价估算成本合计不超过约 ¥0.967；不是精确账单。沿用原累计 20 元授权，历史及本轮预算预留合计 ¥16.351958，账本执行上限 ¥19.95；预留不等于实际花费，不因失败释放预留。无重试调用。

接口行为核对来源：[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)、[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)、[模型及定价](https://api-docs.deepseek.com/quick_start/pricing/)。JSON 模式保证不了本站协议、解释真实性或预测正确，因此仍需本地校验与明确的检查范围提示。
