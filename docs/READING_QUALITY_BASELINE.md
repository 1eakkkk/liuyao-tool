# 结构化解读离线质量基线

日期：2026-09-28。范围为既有四条、已曝光的真实开发回复，不是盲测，不是独立人工验收，也不是模型准确率评估。本轮零网络模型调用、零新增 API 费用。

## 可重复运行

运行 `npm run audit:reading`，报告写到 `test-results/reading-quality/development-baseline.json`。数据来源为 `docs/acceptance/reading-v3-live-review.json`，逐项标注在 `experiments/reading-quality/reviews.json`。

原始回复、问题与引用证据都以 SHA256 绑定；修改原文或证据会拒绝旧评审。脚本检查标注引文确实存在、事实断言与记录值是否相等、同一因素是否直接引用该事实。它不自动理解全文，不把未标注段落视为正确。

范围与支持度由本轮开发代理阅读后给出，不伪装成独立人工或第二模型的判断。程序核对的是这些标注的可追溯性；评级本身仍可被人工质疑和修订。

## 评分规则

| 维度 | pass | partial | fail | unresolved |
| --- | --- | --- | --- | --- |
| 回答范围 | 回应当前要求且未明显越界 | 已回应但展开无关内容 | 未回答核心要求或明显违背范围 | 材料不足以判定 |
| 引用支持 | 所审阅陈述与证据对应 | 局部缺引用或推论无法确认 | 明确事实冲突或关键支持断裂 | 无法核对 |

事实维度报告标注检查数、冲突数，不把未发现冲突称为全文通过。直接引用缺失只说明本段未引用该字段，不自动证明规则引用没有间接支持。事实、范围、支持、生产机械校验独立列出，不生成混合总分。

## 本轮修正

新增正确／错误表达对照时发现：原动静检查先删除句尾问号，会把“第1爻为动爻？”当作断言，导致错误回退。修正为保留句尾符号；疑问句、语气词问句和明确请求核对的表达不作肯定断言。后续独立肯定句继续检查，不因前一句是问题而放过整段。

新增测试先在旧实现复现失败，修改后通过；已有六爻正反断言、条件／否定／引用、真实错误回复与旧会话兼容测试继续保留。本次不改变提示词版本、不重写模型原文、不增加知识库注入，也不把离线评审模块打包到网页。
