# 解读约束离线基线与有限验收

目标是约束输入、事实来源和回答范围，让程序检查与内容审查各司其职。不把格式通过称为解释正确，不用吉凶比例衡量质量，也不以测试数量代替上线成果。

## 本轮范围

2026-10-05，正式选择协议 `structured-selection-2`，任务策略 2、判断策略 2、来源策略 1。只新增离线工具，未修改网站、模型提示词或调用接口。

复用 `experiments/reading-quality/semantic-review.js` 的审查协议；新适配器为 `experiments/reading-quality/constraint-baseline.js`，标准版本 `constraint-rubric-1`。标准作为审查包的一部分参与摘要校验，原回答和当时失败记录分别保留。真实旧回答重放前，重建可信上下文并核对问题、上下文编号、请求消息摘要；不直接信任反序列化上下文。

## 四项标准

| 维度 | 检查内容 | 如何处理未知 |
| --- | --- | --- |
| 事实 | 全文是否与程序记录、用户提供信息冲突 | 未知现实功能不能当作已经证实的错误或事实 |
| 范围 | 是否回应当前问题，擅加应期、盈利目标或无关建议 | 不因缺少预测结论判失败 |
| 出处 | 是否区分用户描述、程序事实、公开来源和模型解释 | 无资料也不能伪造出处；仅无文献且无出处主张才可不适用 |
| 依据 | 取用、因素和最终方向是否有相应支持，解释强度是否超过依据 | 有争议的类象保留不确定；一般建议明确标注 |

每项独立记录通过、失败或不确定，附原回复精确位置和理由。分歧原样保留，不合成一个“准确率”。摘要只能证明审查材料一致，不能证明判断正确。

## 七条固定案例

| 案例 | 预期程序检查 |
| --- | --- |
| 直接断言投入产出合理 | 拦截现实断言 |
| 明确没有证据证明投入产出合理 | 放行否定与一般建议 |
| 未被询问的短期结果预测 | 拦截额外预测窗口 |
| 标明一般建议的短期试用 | 放行使用建议 |
| 未提供依据的多人协作功能断言 | 当前检查放行，记录语义漏检 |
| 明确协作功能未知 | 放行保留未知 |
| 已曝光项目真实回复 | 重放仍因方向依据不匹配而拒绝 |

六条为合成成对对照，一条为已曝光 DeepSeek 原回复。全部属于开发材料，不是盲测。原回复最初的否定语误拦记录保留，当前重检结果另记；不修改旧答案来获得通过。

## 使用

在仓库运行 `node scripts/constraint-baseline.js test-results/<新的目录名>`，得到 `packet.json`、`gates.json`、`review-template.json`。目录必须不存在，文件不覆盖。审查者按包内标准填写模板，再使用已有 `scripts/knowledge-semantic-review.js summarize` 汇总。生成器不接触凭据、不发网络请求。

## 下一次真实验收的收尾规则

1. 开始前固定源码提交、协议与策略、两条问题、人工审核标准、请求消息摘要和预算。未参与调试不自动等于盲测，明确曝光情况。
2. 最多两次完成回答调用，预计预算上限 ¥0.20，同时保留余额至少 ¥1；开始前核对实际定价与余额，不沿用历史价格估算。若不满足预算，减少调用或停止。
3. 不自动重试、不换题刷通过。出现程序错误、出处伪造或明确无依据的现实断言，停止剩余调用并记录失败。
4. 回答保留原文，四项分别审查。明确工程错误修复；取法争议保留争议；预测正确与否另靠后续真实结果记录。
5. 两条完成或触发停止条件即结束本批，不追加样本。若仍有阻断，只报告具体阻断与修正范围，不宣称质量验收通过。

这份规则尚不等于已冻结真实测试：下一轮仍须填入两条具体问题、源码提交与当时价格，再发起调用。本轮付费调用为零。
