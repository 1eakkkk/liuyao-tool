# 测试文件能否删除

核对日期：2026-10-05。核对时 `tests` 约 2.4MB，`test-results` 约 60.3MB；后续运行会继续产生结果。它们都不是线上网站需要读取的数据，但承担不同职责。

| 位置／类型 | 用途 | 删除的影响 | 建议 |
| --- | --- | --- | --- |
| `tests` 中的测试代码 | 核对排盘、协议、历史、费用和其他行为 | 丢失回归检查，CI 或发布流程可能失败 | 保留，随源码版本管理 |
| `tests/fixtures`、回归固定样例 | 固定输入、预期值、真实失败样例等 | 检查失去基准；有些无法凭新模型回答重建 | 保留 |
| `test-results` 的模拟截图、临时浏览器报告、打包清单 | 可重跑的工程产物 | 不影响线上运行，需重新运行才能查看报告 | 验收完成后可删或归档 |
| `test-results` 的真实 API 原始 SSE、JSON、查询／读取响应、请求计划、哈希与审查 | 已付费、当时模型/网页版本的原始证据 | 无法通过重跑重现同一结果；重新调用可能收费 | 建议先归档，勿整批清空 |
| `test-results` 的费用预留／执行／attempt 账本 | 记录既有用量、预算与防重复调用状态 | 后续脚本可能失去预算和防重依据 | 保留有效账本及对应原始证据 |
| `test-results` 的临时 `.mjs` 等脚本 | 早期一次性本机检查工具 | 不是全部可自动重建，历史复放可能依赖它们 | 核实用途后再清理；有效工具应移入 `scripts` |
| `docs/acceptance` | 随 Git 保存的验收摘要与固定证据 | 文档或测试引用可能失效 | 不当作临时结果目录删除 |

`test-results/` 已在 `.gitignore` 中。正式打包只包含页面、JS、CSS、物理引擎及响应头文件；不会将测试目录上传到 Cloudflare。删除本机结果不会加快线上网站，也不删除浏览器中的用户历史。

推荐按已完成的阶段归档到独立备份目录，校验归档可读取后再删除可替代产物。最新阶段的原始请求、回复、预算与防重记录保留在原路径，直到相关检查收尾；目录移动可能影响引用其原路径的复放脚本。不要为了腾空间重新生成付费结果。
