# 知识库阅读包与分层解读：离线开发版

日期：2026-09-30。用户要求继续改进，并考虑增强知识库。

## 这次增强了什么

基于现有已纳入检索的 7 条知识，增加 7 组现代编辑的复核问题、有边界写法与越界写法。覆盖世应方向、月破、月合、静爻日冲、进神、退神、旬空。这些是对已有条件和禁用边界的教学整理，不是新增古籍原文、真实占例或独立验证。底本仍为 1 个，原始片段仍为 9 个，知识单元仍为 10 个，准入仍为 7 个；没有擅自将待核知识升级。

新增离线资料包构建器，保留原文、现代摘要、影像页码、底本及原文哈希、适用条件、禁用边界、例外状态和同命题分组。编辑指导明确单列，不与原文混写。文献只作解释背景，不增加独立证据权重。

生成资料包必须显式指定知识 ID、适用状态和理由。`confirmed` 是调用方复核声明，不是程序已经证明适用。`uncertain`、`not_applicable`、未准入、重复命题和超预算条目不进入包；未选择时为空包。没有自动问题分类、关键词适用推断或线上设置入口。

上限为 4 条；默认整个输入包不超过 8000 Unicode 码点，包含出处、条件及现代指导。完整条目无法容纳时整条排除，不裁掉限制。这个开发预算不是旧 Structured 1.2 的预算，也没有改动旧实验的 2400 字与增量比例约束。

## 分层输出候选

新协议 `layered-reading-dev-1` 保持离线，与线上现有输出协议分离：

| 部分 | 保存的内容 | 当前可检查范围 |
| --- | --- | --- |
| facts | 程序事实 ID 与原始类型的值 | ID 是否为 program_fact、值是否一致 |
| interpretations | 解释、事实引用、文献引用、适用理由、不确定性 | 事实引用是否对应一致值，文献是否确实已选入包 |
| advice | 标明 general_advice 的现实建议 | 字段及标签有效，不允许伪装成证据引用 |
| conclusion | 用户先看到的自然语言结论 | 暂不自动评判支持程度 |

`mechanical_ok` 只代表上述引用及值检查通过。解释支持、问题相关性、结论支持、建议是否实际越界仍为 `unassessed`。即使提供文献和适用理由，也不能由字符串存在性证明理由成立。模型可能在 explanation 或 conclusion 中夹带错误事实，当前校验器不会假装已识别。

调用方应使用经校验的知识索引及 `buildLiteraturePacket` 的输出；输出检查器不是任意外部语料或伪造资料包的认证器。正式接入前还需要完整输入认证、协议迁移、历史记录兼容和浏览器验证。

## 可复现

```text
npm run knowledge:prepare
npx vitest run tests/knowledge/packet.test.js
npm run audit:reading
```

生成到忽略目录 `test-results/knowledge-reading/`：

- `reading-cards.md`：7 条图书出处及编辑使用对照。
- `cards.json`：完整机器可读阅读卡。
- `empty-packet.json`：默认无注入示例及包哈希。
- `output-instructions.txt`：离线分层输出提示约束。

22 项新增测试覆盖不确定/未知/待核知识排除、预算不截断、排序一致、原始值错误和类型错误、文献或规则冒充事实、缺少事实引用、未选文献引用、建议标签和重复来源。测试数据为作者可见的开发对照，不是独立验收，也没有真实模型调用。

本地完整验证：39 个测试文件、449 项测试全部通过；`release:check` 通过，知识模块没有进入生产构建；原有 `audit:reading` 的 102 个标注对照和 168 个明确断言对照结果保持不变。JS／CSS 产物哈希与稳定网站相同。本轮不发布新的线上知识功能。

## 继续推进的门槛

先对这一明确选材、分层输出的方案做小规模开发对照，检查是否减少事实混写、条件丢失和常识建议冒充证据。再由独立收集、未参与开发的样本评估相关性及引用支持。只有确有收益且不增加错误，才考虑 API／外部提示词双入口迁移。

原文扩容应逐页核对完整上下文，优先补足待核条目条件；本轮没有完成新的原典采集，不将现代教学整理计入原典数量。自动知识注入仍未通过发布门槛。未修改冻结实验，未读取或修改用户拥有的未跟踪 holdout 文件，未使用付费 API。
