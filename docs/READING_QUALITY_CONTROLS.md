# 六亲、世应与建议依据：第二轮离线对照

本轮只扩展离线评估，不改变线上协议、提示词和拦截规则，不调用付费 API。

## 六亲与世应

`npm run audit:reading` 在原四条真实开发回复基线之外生成 102 个开发对照：

- 六个爻位 × 六亲／世爻标记／应爻标记 × 正确、错误、引用错字段、引用放在另一段，共 72 个。
- 六个爻位 × 问句、假设、引用原话、变爻、伏神语境，共 30 个。这些没有本爻事实断言标注，因此报告检查数为零，不记作“事实正确”。

各场景使用程序卦盘生成，并显式标注待检查事实。事实冲突与本段引用缺失分开统计：错误事实即使带着真实引用也不通过事实核对；正确事实引用另一个字段或借另一段引用，依然记录本段引用缺失。

**102 个对照通过表示标注审计行为符合预期，不表示自动语义识别率为 100%，更不表示模型生成质量改善。** 原生产校验仍可能接受六亲或世应文字错误，因为它尚未具备完整的自然语言检查。报告同时保留生产机械校验状态，避免掩盖差距。

实现：`experiments/reading-quality/cases.js`。生成报告：`test-results/reading-quality/relative-role-controls.json`。无需 Key，所有输入都是开发用合成数据。

## 一般建议与卦象依据

`experiments/reading-quality/advice-pairs.json` 提供六组开发者编写的反例与有边界的写法：家人协作、旧书数量、预算、时间、纯事实核对、追问。

| 错误跳跃 | 应如何表达 |
| --- | --- |
| 世应比和 → 家人愿意配合且必然成功 | 先询问意愿；盘面关系不能证明现实意愿 |
| 两处父母 → 书很多／必须分两批 | 清点实际书量再决定批次，类象不是计数 |
| 妻财旬空 → 实际缺钱 | 未问预算时不扩展财务；需要购买才核对实际预算 |
| 一般建议时间 → 确定应期 | 按实际日程安排，不添加用户排除的日期预测 |
| 父母持世 → 已决定搬家 | 只报用户要求的世爻和六亲，不补心理或事件 |
| 上轮模型承诺 → 本轮事实依据 | 历史判断不充当事实，错误承诺应明确修正 |

这些是评审标准和表达对照，不是从真实新回复中取得的结果。不会靠“必然”等关键词数量自动给句子评分，否定句和引用反例都可能包含这些词。

## 后续上线门槛

任何新的自动拦截必须先能可靠区分本卦／变爻／伏神、肯定／否定／条件／疑问，并证明不会把正确内容误拦。未满足前维持离线标注与人工评审。一般建议允许出现在答案中，但应明确其常识性质，不能用装饰性引用声称它已被卦盘证明。
