# 当前结构化解读协议

更新：2026-10-09。此文说明正式新会话；旧离线原型和旧历史按原版本处理。实际字段与限制以 `src/ai/output/practical.js`、`contract.js`、`parse.js` 为准。

## 输入与模型职责

会话容器为 `reading-production-4`，新会话使用判断策略 7、`selection-2` 输出格式。API 与导出提示词共用六条基本规则和完整卦盘：先回应问题、解释主要取用与取舍、给具体建议；区分程序事实、用户陈述、公开背景和模型推论。

问题宽泛、静卦、未知名称或没有预设取法卡不会阻止解读。程序不按因素数量决定吉凶，也不使用旧的解答质量检查否决整篇回答。无法确定的现实事实仍须说明限度，不能由卦盘检查冒充已知。

## 模型返回

| 字段 | 用途 |
| --- | --- |
| `schema_version` | `structured-selection-2` |
| `context_id` | 本轮问题、卦盘和会话绑定的标识 |
| `answer` | 完整自然语言正文，直接回答并交代主要理由与建议 |
| `direction` | favorable / unfavorable / mixed / unclear，由模型取舍 |
| `main_choice` | 主要取用的目录编号及理由，可为 none |
| `factors` | 重点解释及有效依据编号；通常两至四项，不要求填满固定组合 |
| `background_usage` | 实际提供的公开背景如何使用，无内容可为空 |
| `timing_candidates` | 模型认为相关的时间候选与依据，可为空 |
| `uncertainties` | 影响本题的不确定性，可为空 |

引用编号由程序解析为本轮爻位、属性及关系；重复引用去重。一般建议允许没有卦盘引用，不会因此编造程序依据。可展开的依据说明与正文分开显示。

## 接收与显示

API 使用一次 `submit_reading` 工具数据返回，不执行任何工具动作。提示词贴回要求用户确认完整复制。两条路径共用解析器和显示逻辑。

1. 完整结构与引用通过：显示正文、倾向及可展开依据；只表示格式和编号已核对。
2. 本轮正文完整可读，附带字段异常：显示正文与未核对提示，保留原返回；不显示不可信的依据卡片。
3. JSON 尾部损坏而开头版本、轮次、正文三个字符串完整：只读取安全的正文前缀，不修补或信任损坏尾部。
4. 中断、截断、另一轮响应、身份歧义或正文无法读取：报告具体技术问题并保留原文，不伪造完整回答，不自动发起付费重试。

所有模型文字按文本处理，不能执行返回的 HTML。可读但未完整核对的正文可保存、复制，并以 `checked:false` 的历史上下文继续追问；历史本身不是事实证据。旧历史不会被自动重写或重新收费。

## 检查与局限

专项测试位于 `tests/output/`；`scripts/verify-practical-browser.js` 覆盖当前初次 API、导出／贴回、追问、异常正文和历史路径。`verify-reading-browser.js` 同时检查旧协议兼容与当前生产版本。

返回结构、网络结束、引用存在可以由程序检查；解释质量、未知事实和预测准确性不能据此保证。完整验收与真实样本局限见 [发布记录](PRACTICAL_READING_RELEASE.md)。
