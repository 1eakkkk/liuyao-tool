# M2：结构化输出离线闭环

日期：2026-09-24。状态：离线原型，未接入真实 API、正式站点或旧会话。用户确认先展示自然语言结论，依据／应期／不确定性可展开；本轮不调用付费 API。

## 已实现的行为

1. 从既有 Canonical 和 r1 规则构建白名单输入及证据目录，不引入知识库。
2. 对问题、输入版本、规则开关、事实和证据目录共同计算 context_id，绑定一份不可修改的内存快照。
3. 提供独立的 JSON 输出协议和提示词，不复用旧版“只返回纯文本”的冲突指令。
4. 对完整回复执行格式、字段、版本、上下文身份和引用校验；用神候选的爻位／本变伏组件／六亲／对应事实引用必须一致。
5. 结论首先显示，用户展开后查看依据、用神候选、应期候选和不确定性。证据值和规则方向从程序快照读取，不接受模型自填的事实覆盖。
6. 无效格式、未知引用、上下文不匹配、截断、主动停止、网络中断和过长回复均退回原始文本，明确未通过校验；不自动修补、不触发第二次模型调用。
7. 所有模型文字以 textContent 渲染，不执行 HTML，也不把模型文字转换成链接。

## 协议与边界

- 输出版本：`structured-answer-1.0`；Prompt：`structured-answer-p1`。
- 必填：schema_version、context_id、answer、direction、yongshen_candidates、factors、timing_candidates、uncertainties。
- direction 是模型判断的枚举，不是概率。协议没有 confidence／成功率字段；未知字段拒绝。
- 候选用神与应期可为空；至少一项有引用的解释因素和一项不确定性。
- 每项解释引用目录中的 fact 或 rule ID。引用存在只能证明来源关联，不能证明文字解释成立。
- rule 的爻位、组件、from/to 与命中快照相同；规则和其来源事实不能被当作两份独立证据重复计权。
- 最大原始回复 64,000 UTF-16 单元，另有字段长度和数组条数上限；超出时仅保留有界原文并标记截断。
- 只解析完整 JSON 对象；Markdown 围栏、前后说明和半截 JSON 不静默提取或修复。
- 流式收集器在完整 stop、DONE 且未中断后才能校验，半段回复始终不是已核对结果。外部回复的完整性由操作者声明，不冒充可观测 API 结束信号。

输入上下文由本地工厂创建且深度冻结。模型不能把自己返回的 context 对象当作可信事实来源；CLI 校验也从操作者提供的 Canonical 重建上下文。context 哈希用于匹配输入，不证明来源真实性，也不是防止本机操作者篡改的认证机制。

## 明确没有实现／不能保证的内容

- 自然语言 answer／reason／interpretation 中的所有事实、因果、方向和预测没有自动语义核验。某个有效引用旁边仍可能写出错误解释。
- 未提供古籍检索；没有验证真实 DeepSeek 是否稳定遵守协议、是否更好或成本如何。
- 现有 API 客户端会做 Markdown 清理和日期后处理，不能直接拿其处理后的 text 当作原始 JSON。下一阶段需要保留原始响应并独立接入收集器，同时保留旧模式兼容测试。
- 未迁移历史会话、未实现结构化追问的持久化／恢复；页面不保存粘贴的回复。
- 未实现真实结果反馈或不可篡改预测锁定；这属于后续里程碑。

因此状态提示使用“格式与引用核对通过”，不会写“解读验证正确”。

## 本地体验

```sh
npm run dev -- --port 4330 --strictPort
```

打开 `http://127.0.0.1:4330/experiments/structured-output/`。

可加载合成的有效样例、测试虚构引用、测试中断，或复制提示词到外部 AI 后把回复粘回校验。示例取自已有兼容测试卦盘，回答由程序编写，明确不是模型实测或真实结果案例。

## 离线命令

```sh
node scripts/structured-output.js prepare --canonical experiments/phase7/fixtures/compat-1.json --output test-results/output-package
node scripts/structured-output.js validate --canonical experiments/phase7/fixtures/compat-1.json --response test-results/response.json --output test-results/output-review.json --completed
```

prepare 创建全新的目录，输出完整提示词、messages、上下文、Schema 与清单。重复目录拒绝覆盖。validate 必须使用同一卦盘和问题；成功退出 0，回退退出 2。没有 `--completed` 时按未完成回复处理。不会访问 API、读取 Key 或记录用量。

文件包含问题和卦盘，真实个人数据应保存在被忽略的本地目录，不能当作公开测试资料提交。命令行不会打印完整回复或密钥。

## 验证与生产隔离

15 项新增测试覆盖上下文绑定／白名单／冻结、24 个既有卦例证据完整性、未知引用、用神组件与六亲、未知字段／概率字段、长度上限、流式完整性、原文回退、HTML 安全呈现、CLI 防覆盖和 Prompt 一致性。

`npm run test:browser:output` 验证桌面 1280／手机 390 宽度：结论、折叠区、引用失败和中断回退、安全文本、无横向溢出；页面异常和外部网络请求均为 0。截图在 `test-results/structured-output/`。

生产构建门槛新增禁止导入 `src/ai/output/`。生产输出的 5 个文件与已发布清单 SHA-256 完全一致。离线原型不会随本次提交进入线上页面。
