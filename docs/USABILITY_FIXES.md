# 2026-09-27 使用反馈修正

本轮针对用户的四项反馈调整使用流程，延续静态前端、用户自带 Key 和提示词导出两种入口。

## 问题与修正

- 首次进入默认显示起卦，不再自动弹教程；收起日期设置，缩短头部与操作说明，帮助和参考知识仍可主动打开。
- 结构化模式过去完全忽略普通风格设置，导致选择深究后仍输出短文。现在 API 与提示词共用篇幅偏好：简洁目标 300–400 字，深究目标 700–800 字，自定义支持语气与篇幅。目标用于 answer 正文，不含折叠依据。纯事实核对仍简短，不为字数扩大回答范围。新会话保存设置快照，恢复与追问使用同一份设置；旧会话保留兼容。页面显示实际正文字数与目标，人设和推理档位在结构化模式禁用并说明。
- 恢复排盘时附加了 `.placeholder` 提示，旧 CSS 把整个排盘误当作空态 flex 容器，造成截图中的横向挤压。空态样式现只匹配唯一占位子元素；真实排盘固定纵向布局，900px 以下使用爻卡片。
- 物理重摇过去未清旧问题，新卦会错误绑定旧问题。现在只有完成六爻、提交新卦时清空；取消确认或取消投掷都保留原问题和原卦。新问题直接绑定新卦，不再追加文字不同确认。AI 自动起卦仍保留其输入问题。
- 复现了真实物理模拟的铜钱立住状态，没有把无正反面的结果强行当作爻。未落稳的当前爻自动重投最多三次，保持已完成爻；仍失败才要求手动再投。前后台物理计算均按约 8ms 时间片让出执行，改善弱设备响应；单个物理步骤可能超过时间片，不承诺硬性帧率。

## 验证边界

使用真实 CANNON 物理模拟检查六爻流程，另有固定立住样本验证必须重投；没有改动排盘算法或通过随机补结果掩盖物理失败。浏览器验收新增恢复历史后 320／390／580／768／1024／1280px 的布局检查、取消保留、重摇清空、新问题直接导出和篇幅传递，覆盖 Chromium 与 WebKit。

WebKit 桌面自动化并非 iPhone 真机，不能保证所有 iOS 版本的性能；本轮没有真实付费 API 调用，篇幅约束传递已验证，但模型实际每次达到目标字数不作保证。
