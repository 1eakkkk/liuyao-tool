# 个人计划取法准入版

## 结果摘要

「个人计划／项目能否推进」这一类已有已核对取法，并在固定小样本上通过验收：**2 次真实调用全部通过校验、零问题**，方向均落在 `unclear`，作用条件逐项标为待核实。

## 这一版修的是什么

上一版把几乎所有问题都答成「当前结构化模式尚不支持这类判断」。原因不是取法保守，而是提问识别只认两种句式：`他能否帮我…` 与 `我能否帮到…`。除此之外一律落到同一个兜底文案，于是「个人计划能否推进」这一类整类失效，上一批留作未覆盖的两个个人项目题就是它的表现。

这一版补上这一类，并把它内部的三种缺口分开报，不再混成一句话。

## 用户能看到的变化

「个人计划／项目能否推进」现在有已核对取法。观察位置是世爻（世为己），可用机制六项，全部来自**已经转录在库内**的段落，不新增古籍、不改古籍数量：

| 机制 | 依据段 | 方向 |
| --- | --- | --- |
| 进神 / 退神 | 進神退神章第二十九 | 化进与所问「继续推进」同向；化退逆向 |
| 回头生 / 回头克 | 動變生尅沖合章第十五 | 变爻对本位动爻的局部方向 |
| 月合 / 月破 | 月將章第十六 | 该爻有用／无功 |
| 日冲旺衰 | 日辰章第十七 | 旺相为暗动、衰弱为日破 |

每一项都写明**适用条件**与**不能说明什么**。原文自身的限制被保留：進神退神章首句即分喜忌，不把化进等同吉利；動變生尅章限定变爻只作用于本位动爻，不推广到全盘。本版**不选用神**，也不把任何单一机制当作计划成败的结论。

提问识别是确定性的，并且明确排除：否定式（不打算继续推进、停止推进、不再投入、我不想继续）、引用与转述、复合问题（还是／或者／同时／以及／另一个问句）、由第三方作主语的问题（朋友想继续做…），以及没有「继续／持续」或既有前提的裸问句。识别器不读懂语义，只是不猜。

### 追问修正：识别范围过窄

初版识别器要求「我想／我要」出现在目的句之前，实测 30 种自然问法只有 9 种被接受 —— 这就是发布后结构化仍答「无法解读」的主因。现已改为在整句中寻找目的句，并在否定判定前拆开「要不要／能不能／该不该／值不值得」这类「A 不 A」问句（它们是疑问，不是否定）；同时补上两处真实漏判：否定意图（我不想继续…）与第三方主语（朋友想继续做…）。修正后 30 种自然问法全部接受，22 个已知非本类问句仍全部拒绝。

### 机制面

另据**六合章第十九**（静爻逢合为合起、动爻逢合为合絆）为静爻世爻增加「日合／合起」一项；并按**日辰章第十七**原话（冲旺相之静爻、冲衰弱之静爻）把「日冲」限定为**只用于静爻**，动爻不再取用。按 4096 种爻和组合统计，可取用比例由 43.8% 升至 **45.1%**。其余卦的世爻为静爻、无合无冲；要覆盖这些需把「旺衰」本身当作独立依据，而现有转录并未如此表述，本版不代为发明。

### 三种缺口分别说明

程序现在按「题目是否已被取法覆盖」判断，而不是按「这一卦碰巧有没有依据」：

- **取法未覆盖**：目前没有适用于这个问题的已核对取法。保留空因素，不生成外部提示词。
- **卦盘依据缺失**：这类问题已有适用取法，但本卦没有取法要求的依据（世爻无动而化进／化退、无回头生克、无月合月破、无日合日冲，也无已核对的世应生克）。明确说明是本盘依据的缺口，并建议重新摇卦或切换普通解读。
- **现实条件未确认**：已有可用的条件性观察，但实际作用前提仍未核实。**这一类不再拦截生成**：仍然给出有限的局部观察，并单独列出需要你确认的事项。

第三类里，凡是标为未确认的作用条件都不作为确定的支持或阻碍；解释只写这个依据对目标意味着什么、以及它不能说明什么。

### 方向与取舍

世爻自身依据的机制方向由题目方向固定（问「继续推进」），程序据此判定因素属于支持还是阻碍；现实前提未确认时，该因素仍是条件性观察，不单独作结论。这一类允许给出有主次的有限方向；此前的协助类仍只作条件性观察。

## 本轮没有做的事

不扩古籍数量、不增加 API 服务商、不改界面结构，未接入任何未通过的三层候选。旧会话、旧历史按原策略读取，不自动升级。

## 验收边界

全量工程检查 94 文件/1124 项在干净提交树上通过。

真实调用分两轮，共 3 次，均未重试：

- 第一轮 1 次：协议层通过，内容层因模型在解释里复述卦盘属性被程序拦下。据此定位到字段说明缺口并修正。
- 第二轮 2 次：**两条回复全部通过校验、零问题**。其中一条与第一轮同盘同题，只差那一行说明（A/B）；另一条首次真正走到「化進」机制。

**可以声称的**：选定类别现在能给出有依据、有主次的有限解读；不能判断时说清具体缺口；解释未越界；作用条件未确认时不作确定支持或阻碍。

**不能声称的**：预测准确率、吉凶倾向的可靠性。第二轮两条回复的方向均落在 `unclear`，样本量为 2，且未做盲测或重复抽样。

**真实调用与当前代码的差异**：三次调用都发生在识别器修正之前，用的是当时那版识别范围。它们验证的是机制绑定、协议与解释边界，**不覆盖**修正后的识别范围；识别范围由离线检查（30 种自然问法全接受、22 个非本类问句全拒绝）与逐字引文钉扎覆盖。第二轮 `plan-advance` 的原始回复列有两项因素，其中一项是动爻上的日冲；日冲限定为静爻后该回复少一项、不再通过，本轮**未改写该回复**，重放检查如实记录了这一点。

两轮记录：`docs/acceptance/plan-admission-live-20261007/README.md`（含卦盘来源与费用更正）、`docs/acceptance/plan-admission-live-2-20261007/README.md`。

上线信息、线上资产核对与回滚目标见 [发布记录](PLAN_ADMISSION_DEPLOYMENT.md)。

两批合计两个「不调用」期望（取法未覆盖、卦盘依据缺失）均已验证拦截且费用为 0。

独立复核按「事实、取法适用、解释边界、取舍」四项做过对抗性核查，确认拦截判定与三种缺口区分成立，并指出已修正的问题：费用算式与高峰时段定义写反、识别器四个否定式绕过、月合／月破判定不对称、验收记录缺少卦盘来源说明。复核之后又发现并修正一处更严重的缺陷：机制查找按目录里恒为 `null` 的 `target` 绑定，使化进／化退、月合／月破、日冲三条机制从未生效；第一轮记录中「该盘依据缺失」的结论即由此而来，已更正。复核意见与更正过程均未删除。

## 已知局限

- 机制覆盖面依赖确定性识别：否定式、复合问题、第三方主语与无延续信号的裸问句一律不取用，因此仍会有问题落到「取法未覆盖」。这是设计选择，不是遗漏。
- 世应生克（世生应／应生世／世克应／应克世／比和）在个人计划这一类中**不取用**：应爻在此不是「对方」，原文献仅就彼此之事授权该方向。因此这一类只用世爻自身的局部方向。
- 未选用神，也未引入父母爻代表计划本身。
