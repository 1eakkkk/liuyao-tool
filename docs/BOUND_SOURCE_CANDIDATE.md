# 程序生成出处、模型声明引用的离线候选

更新：2026-10-01。产品开发恢复后，先处理[四次真实对照](CLARITY_LIVE_EVALUATION.md)暴露的现代条件漏引、出处归属不清问题。本阶段完成协议和离线工具，不把旧回答改成通过，也不接入生产。

## 改了什么

旧候选要求模型同时给出字段、出处类别和逐字引文。新候选让程序从本次资料包生成字段目录，模型只选择实际使用的 `source_id`。程序按目录补出完整原文、现代整理标签及出处元数据，减少模型自行抄写或标错来源的机会。

| 项目 | 本阶段行为 |
| --- | --- |
| 原文、现代摘要、条件、排除及例外 | 程序完整保留为背景；未使用的背景不计作本段依据 |
| 实际声明的引用 | 按具体字段绑定；重复、未知、跨文献及上下文不一致会被拒绝 |
| 现代整理解释 | 每个所选现代字段必须有自己的说明，与程序事实说明分开；摘要不自动当适用条件 |
| 完整出处 | 程序复制保存；资料包整体哈希包含出处与字段顺序，修改后旧绑定失效 |
| 未声明例外 | 显示“当前材料未说明”，不能解释成不存在例外 |
| 空或稀疏明确条目 | 拒绝；不会显示“有明确条目” |

输出版本为 `layered-reading-sourced-dev-2`，提示版本为 `sourced-instructions-dev-3`，目录版本为 `source-field-catalog-dev-1`。旧协议、提示、真实回复和失败记录均保留；线上结构化解读协议不变。

## API 与外部提示词

离线准备覆盖已曝光的月破、月合、旬空三个开发问题，各有不带文献／带文献两份输入，共六份。问题、程序事实、规则和原资料包沿用上一版，只新增程序目录与新版指导。

```powershell
node scripts/prepare-bound-reading.js test-results/bound-reading-next
```

目标目录必须不存在。工具生成冻结计划、哈希封条和六份可复制提示词；提示词的数据与计划中的 API 消息相同。重复运行不能覆盖已有目录。该工具不会读取 Key、预留费用或调用接口，也没有执行真实请求的入口。

冻结输入见 [plan.json](acceptance/bound-reading-20261001/plan.json) 与 [seal.json](acceptance/bound-reading-20261001/seal.json)。这些是准备材料，不是模型输出或调用承诺；其中历史价格日期不能直接用于未来付费执行。

## 验收范围

针对目录、绑定、上下文变化、无文献回答、现代摘要、错误散文和旧协议兼容建立确定性检查；导出检查复算冻结哈希，验证两种输入一致且不可覆盖。独立审查见[验收记录](acceptance/bound-reading-20261001/review.md)。

本轮没有新增付费调用，费用为零。累计测试仍沿用原 20 元授权及保守预留；账户余额不能当成新的测试预算。下一次真实试测应先核对价格、剩余预留和固定小样本计划，再做独立内容审查。

## 仍未解决

后续已完成一次[真实月合回答检查](BOUND_LIVE_EVALUATION.md)，两名审查在该单条回答中均判断通过。以下候选机制的局限仍保留，不能用单例通过替代整体验收。

字段绑定只验证**已经声明**的引用。模型可能遗漏实际使用的字段、混入未引用条件、将现代整理在自由文字中冒充古籍，或不解释原文的“有用／无用”评价。错误散文仍可能通过机械检查，测试明确保留了这一反例。

条件是否适用于当前卦、解释是否获支持、外部原典真实性及预测表现仍未评估。目录哈希绑定资料包，不等于绑定完整问题、事实包或问答轮次。返回结果始终为 `production_ready: false`，不能宣传模型已改善或知识增强已验收上线。

下一阶段：用冻结的小样本检查新版模型输出，独立复核月合两项限制与作者评价是否都准确表达，以及旬空现代限制是否始终归属于整理者；失败或分歧保留，不通过则继续离线修订。
